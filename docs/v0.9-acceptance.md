# v0.9 Acceptance Checklist

v0.9 starts the audit and resilience track. The first slice makes existing
runs easier to scan in the Workbench without replaying runs, executing tests,
or mutating workspace files.

## Current Slice

Run Risk Filter is implemented in the static Workbench. `/api/runs` now exposes
each run's `status` and `risk_level`, and the sidebar can filter runs by risk.
This remains read-only.

## Acceptance Items

| Item | Status | Evidence |
| --- | --- | --- |
| run list payload includes `status` | Implemented / Tested | UI tests |
| run list payload includes `risk_level` | Implemented / Tested | UI tests |
| failed runs are marked `attention` | Implemented / Tested | UI tests |
| sidebar includes Run Risk Filter | Implemented / Tested | UI asset tests |
| filter is read-only and does not replay runs | Implemented / Tested | docs and UI tests |

## Deferred

| Item | Target | Notes |
| --- | --- | --- |
| run replay | Next v0.9 slice | Replay should be read-only first, using stored tool calls. |
| log filters for trace detail | Later v0.9 | Run list risk filter is enough for this slice. |
| workspace risk hints | Later v0.9 | Needs a separate read-only workspace scan. |
| memory review UI | Later v0.9 | Keep memory changes explicit. |
