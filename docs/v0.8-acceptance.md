# v0.8 Acceptance Checklist

v0.8 starts the stronger coding workflow track with read-only guidance over
existing run logs. This slice does not execute commands, retry tools, create
git commits, or change approval behavior.

## Current Slice

Workflow Hints, Failure Summary, and Provider Notice panels are implemented in
the static Workbench. They read existing payloads, display
`verification_commands`, `latest_failure`, and `provider_notice`, and keep the
guidance read-only.

## Acceptance Items

| Item | Status | Evidence |
| --- | --- | --- |
| run detail payload includes `workflow.verification_commands` | Implemented / Tested | UI tests |
| Workflow Hints panel renders verification commands | Implemented / Tested | UI asset tests |
| hints are derived from Task Review changed files | Implemented / Tested | UI tests |
| workflow helper is read-only and does not execute commands | Implemented / Tested | docs and UI tests |
| run detail payload includes failed observations summary | Implemented / Tested | UI tests |
| Failure Summary panel renders `latest_failure` and next checks | Implemented / Tested | UI asset tests |
| failure helper is read-only and does not retry tools | Implemented / Tested | docs and UI tests |
| `/api/health` includes `provider_notice` for FakeLLM and DeepSeek status | Implemented / Tested | UI tests |
| Provider Notice banner renders current provider state without storing keys | Implemented / Tested | UI asset tests |
| README and roadmap document the v0.8 slices | Implemented / Tested | docs tests |

## Deferred

| Item | Target | Notes |
| --- | --- | --- |
| git checkpoint UI | Later v0.8 | Needs explicit confirmation and clear branch/commit rules. |
| automatic test execution | Later | Do not run commands from the browser panel until approval semantics are designed. |
| patch review helper | Next v0.8 slice | Build on diffs, snapshots, workflow hints, and failure summary. |
