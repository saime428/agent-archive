# v1.0 Settings Page Decision

Decision: keep browser settings read-only for v1.0.

Settings Readiness already shows provider, model, DeepSeek key presence, loaded
config files, warnings, and checks in the Workbench. For v1.0, changing those
settings stays in explicit CLI/config-file flows:

```powershell
agent config show --cwd F:\agent
agent config doctor --cwd F:\agent
```

Do not write API keys from the browser. Do not add a browser config writer for
provider/model yet. That path would need secret handling, rollback semantics,
config validation UI, and clearer ownership than the current stdlib Workbench
needs.

Future trigger: add browser-side settings writes only when users repeatedly
need to switch provider/model from the Workbench and the design includes a
safe secret flow that never stores raw API keys in project files.
