# v0.1 Acceptance Checklist

This checklist closes the Core MVP against the design spec. The uploaded paper is
used only as background for lifecycle, verification, and audit priorities; it
does not expand v0.1 into DeepSeek, skills, memory, hooks, or document tools.

## Implemented and Tested

| Item | Status | Evidence |
| --- | --- | --- |
| `agent run "<task>"` executes a fake action loop | Implemented / Tested | CLI and loop tests |
| `agent doctor` reports local environment status | Implemented / Tested | CLI tests |
| `agent runs list` and `agent runs show <run-id>` inspect durable runs | Implemented / Tested | CLI and run-store tests |
| `AGENTS.md` loads as read-only project context | Implemented / Tested | project-instruction and loop tests |
| Config merge uses defaults, global, project, and CLI overrides | Implemented / Tested | config and CLI tests |
| Project config cannot silently reduce safety | Implemented / Tested | config tests |
| Versioned Action and Observation schemas are enforced | Implemented / Tested | action tests |
| Every v0.1 action validates fixed args schemas | Implemented / Tested | action tests |
| Core-generated metadata overrides model metadata | Implemented / Tested | loop tests |
| Parser, policy, sandbox, and tool errors use standard observations | Implemented / Tested | action, loop, tool, and sandbox tests |
| Workspace boundaries reject path escapes, symlinks, and junctions | Implemented / Tested | sandbox and filesystem tests |
| Protected `.agent/runs/` state cannot be modified by model tools | Implemented / Tested | sandbox and tool tests |
| Risky actions require approval and fail fast in one-shot runs | Implemented / Tested | approval and loop tests |
| `--dry-run` skips write tools and shell commands | Implemented / Tested | loop and CLI tests |
| Shell network and shell-wrapper commands are blocked or gated | Implemented / Tested | shell tests |
| ContextBudget truncates large context, outputs, observations, and repair excerpts | Implemented / Tested | budget, tool, and loop tests |
| File reads handle binary, fallback decoding, large excerpts, and line windows | Implemented / Tested | filesystem tests |
| Search uses `rg` when available and Python fallback otherwise | Implemented / Tested | filesystem and CLI doctor tests |
| Durable logs are redacted before write | Implemented / Tested | redaction, loop, and run-store tests |
| Structured patch validates all affected paths before applying | Implemented / Tested | filesystem and loop tests |
| Write tools create snapshots with restore guidance | Implemented / Tested | filesystem, loop, and run-store tests |
| Invalid JSON or invalid args enter a bounded repair loop | Implemented / Tested | loop tests |
| Tool-call logs include trace, repair, policy, and config metadata | Implemented / Tested | loop tests |
| `agent tools list` and `agent config show` expose user-visible diagnostics | Implemented / Tested | CLI tests |
| `agent config doctor` aliases the v0.1 doctor diagnostics | Implemented / Tested | CLI tests |
| `ask_user` is a terminal action that returns a structured user question | Implemented / Tested | action and loop tests |

## Deferred

| Item | Status | Notes |
| --- | --- | --- |
| DeepSeek provider and provider doctor checks | Deferred to v0.2 | v0.1 stays on `FakeLLMClient` |
| Skills list/show/load and progressive disclosure | Deferred to v0.2 | Must not bypass policy or sandbox |
| Memory review, accepted writes, provenance, and undo | Deferred to v0.2 | No automatic memory writes in v0.1 |

| Markdown and Word report generation | Deferred to v0.3 | Not part of Core MVP |

## Current Closeout Default

v0.1 is ready to freeze when `python -m pytest -q` and `git diff --check` pass
on a clean tracked worktree. The local `docs/main.pdf` paper remains reference
material and is not part of the Core MVP commit set unless explicitly requested.
