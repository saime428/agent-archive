# v0.6 Acceptance Checklist

v0.6 starts the Visual Workbench track. The first slice is a local read-only
web UI shell over the existing agent core and durable run logs.

## v0.6 current status

Visual Workbench MVP shell is in progress. This slice establishes the browser
surface, local API bridge, and Apix-inspired workbench layout without changing
tool execution semantics.

## Acceptance Items

| Item | Status | Evidence |
| --- | --- | --- |
| `agent ui` starts a local workbench server | Implemented / Tested | CLI tests |
| workbench binds to localhost by default | Implemented / Tested | CLI and server tests |
| API exposes health/config/tools/runs read-only data | Implemented / Tested | UI tests |
| tools endpoint reuses the same policy categories as `agent tools list` | Implemented / Tested | UI and CLI tests |
| runs endpoint reads redacted durable run summaries and tool calls | Implemented / Tested | UI tests |
| static UI shows an Apix-style rail, run list, summary pane, and details pane | Implemented / Tested | UI asset tests |
| existing `agent run` and `agent chat` behavior remains unchanged | Implemented / Tested | CLI and regression tests |

## Deferred

| Item | Target | Notes |
| --- | --- | --- |
| browser chat submit and streaming events | Later v0.6 | First slice is read-only |
| interactive approval modal | Later v0.6 | Reuse existing chat approval semantics |
| file tree, editor, and diff viewer | Later v0.6 | Build on existing sandbox and snapshots |
| Vue 3 + Vite frontend project | Later v0.6/v0.7 | Static UI keeps the first slice dependency-light |
| Electron desktop shell | v0.7+ | Browser UI must stabilize first |
