# v0.5 Acceptance Checklist

v0.5 turns the single-run CLI into a minimal interactive terminal agent while
preserving the structured action protocol and the existing safety model.

Summary Areas: `agent chat`, ConversationState, interactive approval, session
persistence, explicit context references, status-level live output.

## Implemented and Tested

| Area | Status | Evidence |
| --- | --- | --- |
| `agent chat` command starts a terminal REPL | Implemented / Tested | CLI tests |
| each chat turn calls the existing run loop and prints status/final fields | Implemented / Tested | CLI tests |
| ConversationState injects bounded untrusted history before the current task | Implemented / Tested | chat tests |
| conversation history keeps the current user task as the final user message | Implemented / Tested | chat and loop tests |
| session persistence writes `.agent/chats/<chat-id>/session.json` | Implemented / Tested | chat and CLI tests |
| `agent chat --resume <chat-id>` loads a prior session | Implemented / Tested | CLI tests |
| saved chat session data is redacted before durable storage | Implemented / Tested | chat tests |
| interactive approval can confirm or deny confirmation-required actions | Implemented / Tested | chat and loop tests |
| non-interactive `agent run` approval fail-fast behavior is unchanged | Implemented / Tested | loop regression tests |
| `@file` references load sandboxed, budgeted, untrusted file context | Implemented / Tested | chat tests |
| `@dir` references load sandboxed, budgeted directory listings | Implemented / Tested | chat tests |
| status-level live output reports model calls, actions, tools, and approval waits | Implemented / Tested | CLI tests |

## Deferred

| Item | Status | Notes |
| --- | --- | --- |
| provider token streaming | Deferred | Status-level live output shipped first so JSON action parsing stays deterministic |
| slash commands such as `/help` and `/status` | Deferred | EOF and Ctrl-C are enough for the MVP |
| rich transcript browser | Deferred | Run summaries and session JSON are the current durable view |
| complex planner | Deferred | Chat still uses the bounded action loop |
| native provider tool-call schemas | Deferred | Providers continue adapting to the internal JSON action protocol |

## Manual Smoke

```powershell
$env:PYTHONPATH="src"
python -m agent.cli chat --cwd F:\agent
python -m agent.cli chat --cwd F:\agent --resume <chat-id>
python -m agent.cli run --cwd F:\agent "inspect project"
python -m pytest tests/test_chat.py tests/test_cli.py tests/test_loop.py -q
python -m pytest -q
git diff --check
```

Success criteria:

- Chat prints `chat_id`, per-turn `status`, `completed`, `terminal_reason`, and `final`.
- A second turn receives bounded `UNTRUSTED CONVERSATION CONTEXT`.
- Confirmation-required actions in chat ask for approval before execution.
- Non-chat runs still fail fast when approval is required.
