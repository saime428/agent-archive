# v0.7 Product Shell Decision

Date: 2026-06-28

Status update (2026-07-16): the migration triggers below are now present. This
historical decision remains the baseline for the current static Workbench, but
new frontend work follows [Frontend vNext Direction](frontend-vnext-direction.md).
The existing shell stays in service until the vNext replacement reaches verified
feature parity.

Decision: keep the stdlib static Workbench shell for now.

Do not add Vue, Vite, Electron, or Tauri in this slice. The current static
HTML/CSS/JS Workbench still covers the frozen v0.6 workflow: chat, approval,
files, editing, diffs, snapshots, restore, status, and refresh. A frontend
framework or desktop shell would add build and packaging work before the product
needs it.

## Current Shell

- Backend: Python stdlib HTTP server.
- Frontend: static `index.html`, `app.css`, and `app.js`.
- Runtime: browser-hosted local Workbench at `agent ui`.
- Safety: no UI shell change may weaken sandbox, approval, redaction, snapshots, or durable logs.

## Migration triggers

- state management starts duplicating across panels.
- UI flows require nested routes, multiple editable tabs, or persistent layout state.
- automated browser tests become hard to keep stable with the static page.
- desktop-only integration becomes required, such as tray startup, local file association, or packaged auto-start.
- asset bundling, code splitting, or component reuse becomes cheaper than plain files.

## Deferred Shell Work

- Vue/Vite project scaffold.
- Electron or Tauri packaging.
- Monaco or multi-tab editor.
- Router, global store, and component library.

## Follow-up slice: v0.7 Workbench task review panel

Task review panel is now implemented. It adds a lightweight read-only review panel for the current run: latest action,
last observation, changed files, snapshots, and suggested next manual checks.
Keep it in the static Workbench shell unless one of the migration triggers
actually appears.
