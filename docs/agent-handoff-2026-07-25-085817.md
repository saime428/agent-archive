## 踩过的坑（别重复）

- `reuseExistingServer: false` 只保证"总是新起进程"，不校验应答者是谁。`cli.py:51`
  的 `WORKBENCH_PORT_ATTEMPTS = 200` 会静默退让到 4175，旧 agent 占着 4174 时所有断言
  都会假通过（`Server` 头一样）。必须靠 Node wrapper 预绑定 + 检测 `cli.py:309` 的
  `Port 4174 is busy; trying 4175.` 退让文案。
- `--cwd` 不隔离用户级状态：`config.py:109`、`mcp_config.py:143`、`core/skills.py:268`
  都用 `Path.home()`，所以 wrapper 必须给子进程重定向 `HOME`/`USERPROFILE` 到临时 home。
- Windows 下 `shell: false` 起不了 `.js`/`.cmd` 假 agent，所以留了
  `AGENT_EXE_ARGS_JSON` 这个测试 seam（生产默认空）。
- `_send_static` 的 index 合成只对结尾带 `/` 的路径生效，所以 `/legacy` 必须显式走 308。
- 控制台输出中文会显示成乱码，那只是 codepage 问题，文件本身是 UTF-8，别当成文件损坏。
